# Предварительная проверка аугментации

Сначала проверено отражение по горизонтали с вероятностью 0,5 и
`RandomAffine(degrees=5, translate=(0.07, 0.07), scale=(0.95, 1.05))`
на каждом обучающем изображении. Обучение: 16 эпох, остальные параметры
совпадают с окончательным экспериментом.

Минимальный validation loss составил 0,2767 против 0,2306 у baseline.
Уже на десятой эпохе наблюдалось заметное отставание по валидации,
поэтому решено проверить более мягкую аугментацию. В окончательном
варианте `RandomAffine` применяется с вероятностью 0,25, сдвиг уменьшен
до 3,5%, масштаб до 0,98–1,02. Отражение сохранено.

В `strong/results/` сохранены исходные веса, история и метрики этого
предварительного запуска, в `strong/training.log` его журнал вместе
с журналом обучения baseline. Его тестовая точность 89,81% не используется
как окончательный результат работы. Проверено два варианта, поэтому итог
следует считать результатом небольшого подбора по валидации при одном seed.

В `mild/results/` сохранён второй вариант: мягкая аугментация с первой
эпохи, тоже 16 эпох. Лучший validation loss: 0,2423, тестовая точность:
90,79%. Он уступил baseline по валидации. Для следующей проверки добавлен
начальный этап из 8 эпох без преобразований, после которого аугментация
включается на оставшиеся 8 эпох без сброса оптимизатора.
Всего проверено три режима аугментации. Это небольшой подбор,
а не доказательство универсального преимущества выбранного режима.
