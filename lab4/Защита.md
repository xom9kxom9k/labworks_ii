# Пояснения к лабораторной № 4

**Чем сегментация отличается от классификации?** Классификатор присваивает
класс изображению, а сегментационная сеть каждому пикселю. Здесь выход
для пакета B имеет форму B×1×128×128.

**Что предсказывается?** Вероятность принадлежности пикселя человеку.
После sigmoid значение от 0 до 1; при вероятности не меньше 0,5 ставится 1.
Нулевой логит соответствует вероятности 0,5.

**Какая сегментация реализована?** Бинарная семантическая. Penn-Fudan
содержит маски отдельных людей, но в работе все положительные номера
объединяются в один класс. Разделение стоящих рядом людей на экземпляры
в этой работе не выполняется.

**Почему U-Net?** Кодировщик с MaxPool уменьшает разрешение и собирает
контекст, декодировщик восстанавливает размер. Skip connections передают
признаки высокого разрешения, помогая восстановить границы объектов.
Реализован компактный вариант с двумя уровнями, без предобученных весов.

**Зачем две функции потерь?** BCE обучает бинарное решение по пикселям,
soft Dice учитывает перекрытие всей маски. Их сумма помогает учитывать
положительный класс, который занимает меньше площади, чем фон.
Сглаживание +1 в числителе и знаменателе делает soft Dice определённым
для пустых масок. На выходе сети sigmoid при обучении отдельно не вызывается
перед BCEWithLogitsLoss, потому что он уже включён в устойчивую реализацию.

**Зачем nearest для маски?** Её значения являются метками классов.
Билинейная интерполяция смешивала бы номера соседних людей и фон.
Для RGB билинейная интерполяция допустима.

**Как применяется аугментация?** При чтении обучающего объекта
одновременно отражаются изображение и маска. Независимые случайные
повороты или отражения для двух частей нарушили бы их соответствие.

**Как выбрана модель?** По максимуму глобального IoU человека
на валидационных 25 изображениях. Тестовые 25 изображений
не участвуют в выборе эпохи и порога.

**Что такое IoU и Dice?** IoU есть отношение площади пересечения
предсказанной и истинной маски к площади объединения. Dice удваивает
пересечение и делит его на сумму площадей масок. При одном наборе
TP/FP/FN Dice = 2IoU/(1+IoU). Для средних по изображениям напрямую
применять эту формулу к уже усреднённым метрикам нельзя.

**Почему недостаточно pixel accuracy?** Если большую часть кадра
занимает фон, пустая маска тоже даст высокую долю верных пикселей.
Поэтому основными метриками выбраны IoU и Dice класса человека.

**Какие примеры изображены?** Первые четыре файла тестовой выборки
без отбора по качеству и отдельно четыре наихудших результата по IoU.
Для всех тестовых файлов метрики сохранены в per_image.json.

**Ограничения?** Всего 170 изображений, один seed, сетка 128×128
с изменёнными пропорциями. Разбиение выполнено по изображениям,
похожие сцены могут оказаться в разных частях. Для оценки переноса
нужны отдельные сцены и более разнообразный внешний датасет.
